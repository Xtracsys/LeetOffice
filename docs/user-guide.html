From zero to a team workspace

LeetOffice is a workspace where humans and AI agents share one store — chat, docs, tasks, links — with every change attributed in a git audit trail. No cloud, no accounts, no data leaving your machines. This guide gets you installed, running, and working in about five minutes. It is a standalone file: save it, print it, share it.

One line (macOS & Linux)

curl -fsSL https://raw.githubusercontent.com/Xtracsys/LeetOffice/main/install.sh | sh

The script detects your platform, downloads the right binary, verifies its SHA-256 checksum, installs to ~/.local/bin, and tells you what to do next. If that folder isn't on your PATH, it shows the exact line to add.

From a GitHub release (any platform, no script)

  1. Open the latest github.com/Xtracsys/LeetOffice/releases
  2. Download your binary:
    macOS (Apple Silicon)leetd-VERSION-darwin-arm64
    macOS (Intel)leetd-VERSION-darwin-amd64
    Linux x86-64 / arm64leetd-VERSION-linux-amd64 / -arm64
    Windowsleetd-VERSION-windows-amd64.exe
  3. Verify it: 
    shasum -a 256 -c checksums-VERSION.txt # in the download folder
  4. Make it runnable and put it somewhere on your PATH: 
    chmod +x leetd-VERSION-* && mv leetd-VERSION-darwin-arm64 /usr/local/bin/leetd
macOS Gatekeeper will warn about an unsigned binary the first time. Right-click → Open (or System Settings → Privacy & Security → Open Anyway). Signing/notarization is on the roadmap — see the README's "What it isn't (yet)".

From source

git clone https://github.com/Xtracsys/LeetOffice && cd leetoffice
go build -o leetd ./cmd/leetd   # pure Go, no cgo, no system deps

Check what you built:

leetd version   # e.g. leetoffice v0.1.0 (8abe240) darwin/arm64

Run one command

leetd

No arguments. The daemon starts and prints a local address:

CONSOLE
leetd: UI on http://127.0.0.1:7667 (Ctrl+C to stop)

Open that address in a browser. First run shows the setup wizard — three choices, plain language:

  • Start a new team — this machine keeps the shared store and can invite others. After setup you'll see your team invite code; share it out of band (message it to your teammate however you like).
  • Join a team on my network — coordinators on your LAN are auto-discovered and offered in a dropdown; pick one, paste the invite code, click Join. One click handles the certificate enrollment and encrypted-sync setup.
  • Just me, for now — a private workspace; you can join or start a team later.
Type your name and go. You land in a living workspace: a welcome doc, a #general channel with a greeting, and starter channels — not empty screens.

What just happened on disk

Your workspace~/LeetOffice (default; a git repository — your audit trail)
Node config~/.config/leetoffice/node.json
Team share (coordinator)~/main.git (a bare repo peers sync to)
Identity / certificates~/.leetoffice-identity — back this up; it's your node's membership

Second machine, sixty seconds

  1. Install LeetOffice there (tab 01).
  2. Run leetd → choose Join a team. Your coordinator appears in the dropdown automatically (mDNS); if not, type hostname.local:7443.
  3. Paste the invite code — the coordinator shows it on its Settings page in a dark terminal card, with a regenerate button.
Enrollment issues that machine an mTLS certificate. From then on, both machines sync every few seconds over encrypted, mutually-authenticated TLS. Either can go offline for any length of time — on reconnect it catches up in one exchange.

How sync stays safe

LeetOffice merges at the block level, not the file level. If you and a teammate (or an agent) edit the same document at the same time, both versions are kept and the later one is flagged with a red "conflicting edit" banner you can resolve by editing. Nothing is ever silently overwritten.

More machines

Same join flow, same invite code (regenerate it in Settings whenever you want to rotate access — already-joined nodes keep working).

The persistent menubar

Every page carries the same bar: Chat · Docs · Memory · History · Agents · Settings, with your name on the right so you always know whose changes you're making.

Chat

  • Pick or create channels (+ new channel); Enter sends, Shift+Enter adds a line.
  • The rail shows channels with message counts and People & agents presence — a red pulsing dot means online now, gray means active recently.

Docs

  • Docs → create any type (doc, task, contact, channel, company, email) or open one and edit blocks directly; add new blocks with a type picker.
  • Every save is a git commit attributed to you. Docs are self-contained HTML files you can open read-only in any browser, forever.

Memory & History

  • Memory is the team's auto-maintained context file (what's in flight, open tasks, decisions, owners) — agents read it too.
  • History is the entire audit trail: every change, who made it, when, which files, which commit. Filter by actor with one click.

Connect any MCP-capable AI client

Claude Code, Codex, Cursor, Hermes — anything that speaks MCP can join your team as a teammate with its own identity. The Agents page shows your exact configuration with a copy button; or from a terminal:

leetd mcp-install                    # prints the snippet
leetd mcp-install --client claude --write   # drops .mcp.json here for Claude Code

The snippet looks like:

{
  "mcpServers": {
    "leetoffice": {
      "command": "leetd",
      "args": ["mcp", "--actor", "agent:hermes"]
    }
  }
}

What the agent can do

send_messagepost in any channel (auto-creates it)
list_channelssee the conversation it's joining
read_doc / write_docread and edit documents, block by block
create_task / linkfile work and link anything to anything
searchkeyword always; semantic via local Ollama when available
audit_query / diffinspect history like anyone else
Every agent write is attributed (agent:hermes) in the same git audit trail as yours — and the block-level merge protects your edits from collisions.

Make it always-on

Settings → make always-on registers LeetOffice as a login service (launchd on macOS, systemd on Linux). It starts when you log in, keeps running, and survives reboots — no terminal needed ever again. undo removes it. CLI equivalents: leetd install / leetd uninstall.

Team invite codes

Coordinators: Settings shows the current code in a terminal card with regenerate invite code. Rotation invalidates the old code but never kicks out already-enrolled machines.

Everything else on the page

  • Your name — the attribution stamped on every change you make
  • Sync every — cadence in seconds (default 5)
  • Ollama URL / model — point at a local Ollama to upgrade search to semantic; leave as-is for keyword search that always works
  • sync now — force one sync cycle

Backups

Your entire team's world is two folders: the store (default ~/LeetOffice) and the share (~/main.git on the coordinator). Both are plain git repos — copy them to any backup disk (encrypting that disk is a good idea) and you've backed up everything, history included.

Quick answers

"address already in use" / UI won't start Another LeetOffice (or app) holds port 7667. Stop the other one, or set a different listen.http in ~/.config/leetoffice/node.json.
Join failed — "could not reach enrollment" Use the coordinator's enrollment address (port 7443 by default — shown on its Settings page), not its sync port. Same Wi-Fi/network? mDNS usually fills this in for you.
Teammate joined but seems on a separate team Run leetd version on both machines — both need v0.1.0+ (the join fix). Re-join with leetd enroll --coordinator host:7443 --secret CODE.
IPv6 mDNS note in the console One line saying IPv6 multicast is unavailable is normal on many networks; discovery continues over IPv4.
Messages/docs not appearing on the other machine Check History on both — sync errors log there. Confirm both nodes' Settings show the same team share. sync now forces a cycle.
Joined node logs repository not found v0.1.0 named the coordinator share ~/main-share.git while joiners asked for /main.git. Upgrade the coordinator (this build serves both names). Or migrate: mv ~/main-share.git ~/main.git, set main_share in ~/.config/leetoffice/node.json to file://…/main.git, restart. Already-joined clients keep their leet://host:7666/main.git URL.
Upgrade Replace the binary, restart (or it restarts itself if always-on). Stores are forward-compatible; leetd check self-tests.
Full uninstall leetd uninstall (service), delete the binary, and — if you really want everything gone — ~/LeetOffice, ~/main.git, ~/.config/leetoffice, ~/.leetoffice-identity.
